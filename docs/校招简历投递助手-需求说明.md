# 校招简历投递助手：需求说明与 MVP 方案

## 1. 需求判断

当前需求可以拆成三个目标：

1. **提高匹配质量**：根据岗位 JD 找到简历中真实可证明的经历，减少“一份简历投所有岗位”。
2. **降低重复劳动**：复用个人事实库、项目经历和常用材料，快速生成定向草稿。
3. **管理投递闭环**：知道投了哪些岗位、处于什么状态、下一步何时跟进，并能复盘哪些岗位更容易进入下一阶段。

首版采用命令行工具，输入是用户维护的 `profile.json`、岗位 JD 文本和投递记录；输出是匹配分析、定向简历 Markdown 和投递状态汇总。它不自动登录招聘平台，也不自动点击最终提交。

## 2. 目标用户与场景

**目标用户**：准备参加秋招/春招的在校生，岗位方向可能包含后端、算法、数据、测试、产品等。

**核心场景**：

- 收到一个 JD，先判断自己的经历是否值得投。
- 从真实项目中选出最相关的 2～4 个项目，调整顺序和关键词表达。
- 投递后记录截止时间、笔试/面试状态和下一步行动。
- 一周或一月后复盘投递量、转化率和常见缺口。

## 3. MVP 功能范围

### P0：必须有

| 功能 | 输入 | 输出 | 验收标准 |
|---|---|---|---|
| 个人事实库 | 姓名、教育经历、技能、项目 bullet、成果 | `profile.json` | 每条经历可单独核验，不要求联网 |
| JD 匹配分析 | `.txt`/`.md` JD | 关键词覆盖率、匹配项、缺口、证据映射 | 缺口被标记为“待补证据”，不能自动写入简历 |
| 定向简历草稿 | 事实库 + JD | Markdown 草稿 | 只重排和复用原文，不生成雇主、指标、职责等事实 |
| 投递跟踪 | 公司、岗位、状态、日期、下一步 | JSON 记录和列表/汇总 | 能新增、查看、按状态统计 |

### P1：验证 MVP 后再做

- PDF/DOCX 导出和格式预览。
- JD 批量导入、截止日期提醒和重复岗位去重。
- 简历版本差异比较，记录每次修改对应的岗位。
- 面试题、笔试链接和联系人字段。
- 可选 LLM 辅助改写，但所有新增事实必须先进入“待确认”队列。

### 暂不做

- 自动登录、绕过验证码、批量自动提交。
- 自动爬取需要登录或违反平台条款的岗位数据。
- 根据关键词猜测用户没有经历过的技能或业绩。

## 4. 用户流程

```text
初始化事实库
  ↓
导入一份 JD
  ↓
分析匹配度和证据缺口
  ↓
人工确认项目顺序与表述
  ↓
生成定向简历草稿
  ↓
人工检查 → 在招聘平台投递
  ↓
记录状态、下一步行动和结果
  ↓
定期复盘转化率与缺口
```

## 5. 关键业务规则

1. **真实性优先**：工具只能使用 `profile.json` 中的事实；JD 里的要求只能作为匹配依据。
2. **证据可追溯**：每个命中关键词至少关联技能清单或项目名称；没有证据的词进入缺口。
3. **覆盖率不是录用概率**：分数只表示文本层面的匹配程度，不能替代岗位判断。
4. **人工最终确认**：任何草稿在外部投递前都需要人工核验日期、数字、职责和链接。
5. **隐私本地化**：首版数据只保存在本地 JSON/Markdown，不上传简历和个人信息。

## 6. 非功能要求

- Python 3.11+，不依赖外部 API，断网可运行。
- Windows PowerShell 和 macOS/Linux shell 均可执行。
- 输入文件编码统一为 UTF-8；错误时给出文件路径和可修复提示。
- 命令幂等：重复执行分析不会修改事实库；投递记录只在显式 `add` 时新增。
- 结果可读：Markdown 可以直接检查、复制到其他编辑器或进入后续导出流程。

## 7. 使用方式

```powershell
# 初始化
python tools/resume_delivery_assistant.py init --dir resume_workspace

# 编辑 resume_workspace/profile.json，并把 JD 保存为 resume_workspace/jobs/backend-001.md

# 分析 JD
python tools/resume_delivery_assistant.py analyze `
  --profile resume_workspace/profile.json `
  --job resume_workspace/jobs/backend-001.md

# 生成定向简历草稿
python tools/resume_delivery_assistant.py tailor `
  --profile resume_workspace/profile.json `
  --job resume_workspace/jobs/backend-001.md

# 记录投递和查看汇总
python tools/resume_delivery_assistant.py track add --company "示例公司" --role "后端开发" --status 已投递
python tools/resume_delivery_assistant.py track list
python tools/resume_delivery_assistant.py track report
```

## 8. 成功指标

首轮验证建议观察：

- 单个 JD 从阅读到生成定向草稿是否能控制在 5 分钟内。
- 生成草稿需要人工修改的事实错误数为 0。
- 每周投递记录完整率 ≥ 90%。
- 用户能从分析报告中明确知道“适合投、需要补证据、暂不适合投”三类岗位。

## 9. 后续产品决策点

在加入 LLM、浏览器辅助或提醒前，需要补充三项信息：目标招聘平台、简历最终格式（Markdown/DOCX/PDF）以及是否愿意使用 API 处理个人信息。没有这些信息时，当前本地 CLI 是成本最低且可验证的方案。
